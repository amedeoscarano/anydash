# Rules

`rules/source/*.yaml` is the single source of truth. Everything else (`RULEBOOK.md`, each skill's `references/rules.md`) is generated by `scripts/build-references`.

## File format

One file per area. Top level: `area`, `prefix`, `rules` (list).

```yaml
area: navigation
prefix: NAV
rules:
  - id: NAV-001                 # <PREFIX>-<3 digits>, unique, never reused
    title: Short noun phrase
    rule: One imperative sentence.
    why: The reason, in one or two sentences.
    source: observed            # documented | observed | inferred (strongest available, in this order)
    evidence:                   # one entry per core portal, always all three; optional portals may follow
      - {portal: portal_a, status: observed, page_type: settings_page}
      - {portal: portal_b, status: absent, page_type: settings_page}
      - {portal: portal_c, status: documented, page_type: other}
      - {portal: portal_d, status: observed, page_type: global}   # optional, at most once
    confidence: high            # high = 3 supporting portals or source documented | medium = 2 | low otherwise
    applies_when: When the rule applies.
    exceptions: When it does not.
    do: Short good example.
    dont: Short bad example.
    check_static: How to verify on code, spec or screenshot.
    check_live: How to verify in a running browser.
```

`source: documented` means a public design guide (e.g. a design system) states the rule explicitly; it allows `high` even when fewer than 3 portals show it live, as long as at least one does or the guide is the portal's own.
Core portals: `portal_a`, `portal_b`, `portal_c`, listed in every rule. Optional portal: `portal_d` (reference portal D, studied for navigation and the global chrome around it), listed at most once and only where it was looked at. A supporting portal is any evidence entry whose status is not `absent`; optional portals count like core ones. Confidence is a ceiling the validator enforces: `high` needs 3 supporting portals or `source: documented` (with at least one supporting portal), `medium` needs 2, anything else is `low`; `source: inferred` is always `low`. Adding an optional portal never raises a confidence on its own; a raise needs a review.
`status`: `observed` (seen live), `documented` (public docs only), `absent` (looked for, not there or contradicted).
`page_type`: home | index | detail | form | settings_index | settings_page | wizard | integration | branding | other | global.
A rule without a usable `check_static` or `check_live` is rewritten or dropped.
No account ids, project ids, organization or store names, customer data or screenshots of the reference portals, ever.
